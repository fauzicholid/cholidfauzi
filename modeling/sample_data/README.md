# Placeholder RTRW pola-ruang sample

**This is NOT the official RTRW Provinsi Jawa Barat dataset.** It is a small,
made-up polygon layer generated by `generate_placeholder_rtrw.py`, used only
to exercise the CNN pipeline end-to-end (label rasterization -> patch
extraction -> training -> full-raster prediction) with real West Java
coordinates and real RTRW pola-ruang class names, before real data is wired
in.

## What's real vs. placeholder

| | Real | Placeholder |
|---|---|---|
| Location | ~3 km x 3 km window near Bandung, verified inside `preprocessing/aoi/west_java_boundary.geojson` | — |
| Class names | Actual RTRW pola-ruang categories (Kawasan Hutan Lindung, Kawasan Pertanian Lahan Basah/Kering, Kawasan Perkebunan, Kawasan Permukiman Perkotaan/Perdesaan, Kawasan Industri, Badan Air) | — |
| Polygon boundaries | — | A plain 4x4 grid with a random class per cell, not the actual zoning geometry |
| Raster values | — | Random integers standing in for Sentinel-2 B02/B03/B04/B08; not real reflectance |

Because the "classes" here are just an arbitrary grid with no real spectral
signal, the ~97% validation accuracy this produces is **not** a meaningful
accuracy estimate -- it mainly reflects that neighboring pixels' overlapping
patches leak into both the train and validation split. It only demonstrates
that the code paths work.

## Get the real data

The official pola-ruang dataset is published by the West Java provincial
government; this sandboxed environment's network egress proxy blocks direct
access to these portals, so fetch it yourself and swap it in:

- https://opendata.jabarprov.go.id (search "pola ruang" / "RTRW")
- https://satupeta.jabarprov.go.id
- https://tanahair.indonesia.go.id/sdi (Ina-Geoportal / ATR-BPN)

## Regenerate the placeholder

```bash
python generate_placeholder_rtrw.py --output-dir modeling/sample_data
```

## Run the pipeline against it

```bash
python prepare_training_patches.py \
    --image sample_data/synthetic_sentinel2_stack.tif \
    --label-vector sample_data/rtrw_polaruang_placeholder.geojson \
    --label-field kelas_pr --patch-size 9 \
    --output sample_data/training_patches.npz

python train_cnn.py --patches sample_data/training_patches.npz \
    --model-dir sample_data/runs/placeholder_v1 --epochs 5

python predict_lulc.py --image sample_data/synthetic_sentinel2_stack.tif \
    --model-dir sample_data/runs/placeholder_v1 \
    --output sample_data/lulc_prediction_placeholder.tif
```

## Swapping in the real dataset

1. Replace `rtrw_polaruang_placeholder.geojson` with the real pola-ruang
   layer, and use its actual attribute column in place of `kelas_pr`.
2. Replace `synthetic_sentinel2_stack.tif` with real output from
   `preprocessing/sentinel2_mosaic_clip.py` + `stack_bands.py` covering the
   same AOI.
3. Re-run `prepare_training_patches.py` / `train_cnn.py` / `predict_lulc.py`
   unchanged -- both scripts only care about the `--label-field` name and
   band order, not where the data came from.
